## COBOL - COmmon Business Oriented Language. COBOL is a compiled language. (COBOL -> Machine Code)

* Interactive Program - Interacts with a user, displays outputs & reads inputs from a screen.
* Batch Program - Runs without interacting with the user and typically processes data in files.

When developing a professional interactive program, you will likely use non-standard extensions such as CICS (Customer Information Control System). The first example in S1C1 is an interactive program that displays the sales tax for the amount of a purchase. The user presses 0 when they'd like to exit.

### Chapter 1, Figure 1-4 (c1-f1-4.cbl)

```cobol
       IDENTIFICATION DIVISION.
      *
       PROGRAM-ID. CALC1000.
      *
       ENVIRONMENT DIVISION.
      *
       DATA DIVISION.
      *
       FILE SECTION.
      *
       WORKING-STORAGE SECTION.
      *
       77  END-OF-SESSION-SWITCH   PIC X VALUE 'N'.
       77  SALES-AMOUNT            PIC 9(5)V99.
       77  SALES-TAX               PIC Z,ZZZ.99.
      *
       PROCEDURE DIVISION.
      *
       000-CALCULATE-SALES-TAX.
      *
           PERFORM 100-CALCULATE-SALES-TAX
              UNTIL END-OF-SESSION-SWITCH = 'Y'.
           DISPLAY "END OF SESSION".
           STOP RUN.
      *
       100-CALCULATE-SALES-TAX.
      *
           DISPLAY "--------------------------------".
           DISPLAY "TO END PROGRAM, ENTER 0.".
           DISPLAY "TO CALCULATE SALES TAX, ENTER SALES AMOUNT.".
           ACCEPT SALES-AMOUNT.
           IF SALES-AMOUNT = ZERO
               MOVE "Y" TO END-OF-SESSION-SWITCH
           ELSE
               COMPUTE SALES-TAX ROUNDED = 
                  SALES-AMOUNT * .0785
               DISPLAY "SALES TAX = " SALES-TAX.
```

### Every COBOL program has four necessary divisions which organize the code:

* **IDENTIFICATION DIVISION** - What program is this? (Identity/header.)
* **ENVIRONMENT DIVISION** - Where does the program operate?  (I/O, Files, etc.)
* **DATA DIVISION** - What data does the program work with? (Variables, data structures, etc.)
    * **FILE SECTION**
    * **WORKING-STORAGE SECTION**
* **PROCEDURE DIVISION** - What does the program actually do? (Executable statements & business logic.)

### Periods are used throughout the program:

* Ends of division & section headers.
* Ends of paragraph names like `000-CALCULATE-SALES-TAX.` & `PROGRAM-ID.`
* Ends of data descriptions in the `WORKING-STORAGE SECTION.` of the `DATA DIVISION.`
* Ends of statements in the `PROCEDURE DIVISION.`

The code starts running from the first executable statement of the `PROCEDURE DIVISION` down unless the flow is altered by a `PERFORM` or `PERFORM UNTIL` statement which may skip down to different procedures like in `C1-F1-4.cbl`

### COBOL Basic Rules & Standards:

* The first six columns in each line are left blank, the compiler later on adds sequence numbers into these positions.
* The seventh column in each coding line can be used to identify a line as a comment with an asterisk.
* Columns 8 through 11 in each line are referred to as the A margin, and 12 through 72 as the B margin.
    * Some code elements like division/section/procedure names, 77 level numbers, and 01 level numbers must start in A.
    * Coding lines that don't start in A must start in B.
* Columns 73 through 80 aren't used, they were originally for program names on punchcards.
* Standards over time have decreased the strictness of columns and margins.
* The COBOL compiler is NOT case-sensitive. You can type code in either or both upper/lower. Best stick to one.
* Mainframes typically use single-quotes whereas smaller computers use double-quotes for quotation marks.
* One space is treated the same as any number of spaces in sequence. Thus you can tab for readability.

### The Identification Division:

* The only required fields are the division header and the `PROGRAM-ID.`
* Some compilers might be more restrictive, like the IBM Mainframe wants program IDs to be 8 characters.
